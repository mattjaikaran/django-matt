  <behavior>
    - Test: Default blacklist backend is "cache" (not "null") when no explicit config
    - Test: `abulk_revoke_tokens_for_user(user)` stores a per-user revocation sentinel in cache with TTL = refresh_token_lifetime
    - Test: `ais_user_tokens_revoked(user_id, iat)` returns True when iat < sentinel timestamp, False otherwise
    - Test: `averify_access_token` rejects tokens issued before the user's revocation sentinel timestamp
    - Test: After `change_password`, old token is rejected with 401 (integration)
    - Test: After `logout`, the logged-out token is blacklisted (individual JTI blacklist, not bulk)
    - Test: Startup warning emitted when DEBUG=False and backend is "null"
    - Test: Existing blacklist tests that assert default=null are updated to explicitly configure backend="null"
  </behavior>
  <action>
    1. **django_matt/auth/blacklist/config.py**: Change default from `"null"` to `"cache"` on line 20. This is the single most impactful security change.

    2. **django_matt/auth/blacklist/core.py**: Add two new public functions:
       - `bulk_revoke_tokens_for_user(user_id: int | str) -> None` (sync)
       - `abulk_revoke_tokens_for_user(user_id: int | str) -> None` (async)
       Both store a per-user revocation sentinel key `{cache_prefix}user_revoked:{user_id}` with value = current timestamp, TTL = `jwt_config.refresh_token_lifetime.total_seconds()`.
       - `is_user_tokens_revoked(user_id: int | str, iat: float) -> bool` (sync)
       - `ais_user_tokens_revoked(user_id: int | str, iat: float) -> bool` (async)
       Both check if sentinel exists and `iat < sentinel_timestamp`. For null backend, these are no-ops (return False).

    3. **django_matt/auth/jwt.py**: In both `verify_access_token` and `averify_access_token`, after existing blacklist JTI check, add per-user revocation sentinel check:
       ```python
       # After JTI blacklist check:
       from django_matt.auth.blacklist.core import ais_user_tokens_revoked
       if payload.iat and await ais_user_tokens_revoked(payload.sub, payload.iat):
           raise InvalidTokenError("Token has been revoked")
       ```
       Ensure `iat` is populated in `create_access_token` (it likely already is via `datetime.now(tz=UTC).timestamp()`).

    4. **django_matt/auth/controllers.py**: In `change_password` method, after `user.set_password()` / `await user.asave()` and BEFORE `acreate_token_pair`, call:
       ```python
       from django_matt.auth.blacklist.core import abulk_revoke_tokens_for_user
       await abulk_revoke_tokens_for_user(user.pk)
       ```
       This ensures old tokens (including from other devices) are invalidated before new ones are issued.

    5. **django_matt/apps.py**: In `DjangoMattConfig.ready()` (or equivalent AppConfig), add startup warning:
       ```python
       import warnings
       from django.conf import settings
       if not getattr(settings, 'DEBUG', True):
           from django_matt.auth.blacklist.config import blacklist_config
           if not blacklist_config.enabled:
               warnings.warn(
                   "JWT blacklist backend is 'null' — token revocation is disabled. "
                   "Set DJANGO_MATT_JWT['BLACKLIST_BACKEND'] = 'cache' for production.",
                   stacklevel=2,
               )
       ```

    6. **django_matt/cli/doctor.py**: Add a Warning-tier check: "JWT blacklist backend is 'null' — token revocation disabled" when `blacklist_config.enabled` is False.

    7. **tests/test_blacklist.py**: Update tests that assert `backend == "null"` as default. They should now explicitly set `DJANGO_MATT_JWT={"BLACKLIST_BACKEND": "null"}` via `@override_settings`. Add new tests for bulk revocation functions.

    8. **tests/test_auth.py**: Add:
       - `test_logout_blacklists_token`: Issue token, call logout endpoint, reuse token, assert 401.
       - `test_change_password_revokes_old_tokens`: Issue token, change password, reuse old token, assert 401.
  </action>
